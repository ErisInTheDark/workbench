- Keep npm bootstrap limited to toolchain provisioning, public CLI registration, and checkout locating/cloning/handoff. Clone current main only for installation; never update existing source implicitly. Settings can record the running checkout as the ready installation under the installer lock; this is the only way an existing clone becomes an installation.
- Incomplete installs resume after consent: record the location before provisioning, never delete the recorded checkout, reuse it when valid, and default the location prompt to it. Use Vite+ for pinned checkout runtime and dependencies. Register the public CLI through the invoking package manager.
- Keep managed toolchains and their receipts in the Workbench data root, never the Workbench Library. Installation and repair reuse the recorded executable and directory environment.
- Provider runtimes and npm MCP server packages install on demand under the data root through the daemon Node's bundled npm, never into the checkout or PATH tools. An install is committed only by renaming its verified, marked staging directory into place.
- Keep native binaries committed; run only their data-root staged copies, never checkout files. Missing platform artifacts must not prevent repository installation or trigger automatic native builds.
- Preserve ordinary daemon CLI shell dispatch. Managed threads cannot install or launch the app.
- Self-update changes only each daemon's own checkout: that daemon fetches and pulls it under its worktree Git transition lease; the app sequences pull and reload. Another device's checkout pulls from this app only when its lockfile is unchanged, then reloads only that daemon's scopes. `client:install` is dirty only while installed dependencies differ from the lockfile; launching entry points resume its repair journal with built-ins before loading `node_modules`, while `wb view` only watches, cancels or retries it. Installs and process restarts cover only processes whose importer closures changed; escalated repairs stop everything. Cancelled or network-failed repairs keep their rung and delete nothing.
