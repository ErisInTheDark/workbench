- User-facing sidebar threads and subagent threads have separate state semantics. Never infer subagent changes from sidebar thread requests. Plan subagent changes separately and obtain explicit user agreement.
- Stop is only ever requested by user or parent agent. Interrupt is everything else.
- A provider turn failure is a thread error: `needsAttention/providerFailed` holds its message until any continuation replaces the lifecycle. Workbench auto-continues only a failure attributed to a usage limit, by the provider's signal or by its account being at a usage cap; never any other, and never over a held questionnaire.
- A bare `interrupted` lifecycle means the turn's process ended: user controls leave a held question or `stopped` instead. Workbench auto-continues it unless the thread has been idle past the auto resume threshold.
- Snooze is app-owned; daemons never store or decide it. Snoozing working sidebar threads preserves their turn; leaving working wakes them. Non-working sidebar threads cannot stay ordinarily snoozed while holding editable claims or sealed-proposal guards; dependent snooze may retain both until its targets clear. Questionnaire snooze interrupts and retains the question; dependent snooze leaves it live; both wake when it leaves; live approvals cannot be snoozed. User compact over a sidebar questionnaire holds it first, as questionnaire snooze does; live approvals block compaction. Stop and complete dismiss pending input and wake the thread.
- A durable questionnaire exists only while its sidebar or subagent thread is pendingInput for that key.
- Agent status does not end an active sidebar or subagent turn. Apply completed/blocked on matching successful turn completion; stop, failure and pending input take precedence. A subagent's successful turn end without a status completes it.
- Accepted provider intent wakes the thread, drops any held sidebar questionnaire, and marks the accepted turn working. A subagent's held questionnaire ends only when its parent's message settles it.
- Relationship-addressed parent messages may settle a child questionnaire.
- Provider list snapshots seed unknown rows only; a lifecycle with a known turn changes through that turn's events. Snapshots may end only turnless provider-owned lifecycles.
- Settled and archived are placement, not status. Preserve lifecycle presentation.
- Live claims, required todos and addressed feedback hold settlement; addressed feedback releases only when resolved or detached.
- Settlement serializes only with Git ownership transfers involving that thread; unrelated Git work never delays it.
- Subagent settle attempts every selected child and reports each outcome. Handover moves a child's Git claims, saved stash and todos to its parent before settling; rejected Git adoption leaves that child unchanged.
- Settled sidebar threads archive 14 days after the later of their last thread item or settling, including existing records. Pins are app-owned and never exempt them: a settled thread keeps its pin only so restoring returns it pinned, and archiving drops the pin.
- Transcript payload retention uses the current settlement generation. Restoring or re-settling starts a new generation; old tombstones never suppress new turns.
- Thread activity time advances only when the canonical transcript admits a new thread item, to that item's observed time. Providers and lifecycle transitions never set it.
- A dependent-snooze source owns its target set; targets may live on any daemon. Target readiness removes one membership. Only an empty set wakes the source. Unreachable targets keep waiting.
- A thread has one live turn: admitting a turn settles earlier unsettled turns, and their undelivered agent-message steers resend into the new turn.
- Agent messages never compact a sidebar thread or start a turn over its held questionnaire: when compaction is due or a questionnaire's turn is not live they are held pending and the send succeeds; a completed thread needs attention; the holds steer its next running turn.
- Before a thread first enters a declared mode, only thread_state, recall and messaging tools run. After a completed compaction, edits and entering checklist-gated modes wait until an unfiltered own-thread recall and the compaction checklist follow it.
- A thread's workflow selection is recorded at creation; messages without `workflowIds` keep it. Cross-folder subagents start on the default workflow.
- Promotion is one-way and owned by the child's daemon: an unsettled subagent becomes a top-level thread, its parent relationship ends, and a former remote parent stays in its network history.
- Until promoted, cross-folder and cross-daemon subagents keep subagent semantics; the child's daemon owns its lifecycle and lists it as its own sidebar row, the parent's daemon owns the relationship, a parent's unsettled remote children hold its task status like local ones, and handover never crosses folders. A child's sibling roster is the parent's latest pushed snapshot; stale rosters reject, never admit.
- A subagent is a thread: its drafts, composer context and file scope belong to its own owner, never its parent's.
